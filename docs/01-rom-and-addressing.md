| mapper | **HiROM + FastROM** ไม่มีหัวไฟล์ (headered = false) |
| ขนาดต้นฉบับ | 3,145,728 ไบต์ (3 MB) |
| ขนาดหลังขยาย | 4,194,304 ไบต์ (4 MB) |

ไฟล์อยู่ที่ `rom/Dai-4-ji Super Robot Taisen (Japan) (Rev 1).sfc`
**ห้ามแก้ไฟล์ต้นฉบับ** ทุกอย่างเป็น build artifact ที่สร้างใหม่ได้เสมอ

## การแปลงที่อยู่

```
pc = ((bank & 0x3F) << 16) | address        # HiROM
```

ตัวอย่าง `$D2:9009` → `0x12 << 16 | 0x9009` = `0x129009`

ธรรมเนียมของโปรเจกต์: ช่วงที่อยู่เขียนแบบ **start รวม / end ไม่รวม** เสมอ
และอ้าง CPU address ด้วยแบงก์ `$C0`–`$FF`

## กับดักที่แพงที่สุด — มิเรอร์ `$80`/`$81`

เอกสารและตาราง hook ทุกที่เขียนว่าเครื่องยนต์ข้อความอยู่ที่ `$C1:xxxx`
แต่ **เกมรันโค้ดจากมิเรอร์ `$80`–`$BF`** เวลาใช้ debugger หรือ watch ต้องดัก
`$81:8402` ไม่ใช่ `$C1:8402` — ดักผิดแบงก์แล้วจะได้ศูนย์ hit ทั้งที่โค้ดนั้นทำงานอยู่
ซึ่งหน้าตาเหมือน "โค้ดไม่เคยถูกเรียก" ทุกประการ ดู `07-pitfalls.md`

## พื้นที่ขยาย

ต้นฉบับ 3 MB กินถึง `$EF` การขยายเป็น 4 MB ทำให้ได้แบงก์ `$F0`–`$FF` (1 MB) มาใช้
สิ่งที่ต้องรู้:

- pointer ภายในแบงก์เดิม **กว้าง 16 บิต** สตริงจึงย้ายออกนอกแบงก์ตัวเองไม่ได้
  เว้นแต่จะย้ายทั้งตารางแล้ว repoint ด้วยตัวชี้ 24 บิตของตารางแม่
- ระบบเก่าเคยใช้พื้นที่ขยายแบบนี้ (ตัวเลขจากบิลด์สุดท้าย): `$F0`–`$F9` ใช้เต็มเกือบหมด
  (สคริปต์ที่ repack), `$FA` ~15 KB (catalog ที่ย้าย), `$FC`/`$FD`/`$FE`/`$FF`
  (ตาราง routing, renderer, hook trampoline) และ **`$FB` ว่างทั้งแบงก์**
- checksum/complement ต้องคำนวณใหม่ทุกครั้งที่เขียน ROM (เครื่องมือเดิมทำให้อัตโนมัติ)
