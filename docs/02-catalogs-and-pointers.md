# 2. Catalog และตาราง pointer

ข้อความเกือบทั้งเกมเข้าถึงผ่าน **ตารางแม่ที่ `$C9:00D8`** — 19 ช่อง ช่องละ 3 ไบต์
เป็นตัวชี้ 24 บิตไปยัง "ตาราง pointer 16 บิต" อีกทีหนึ่ง

```
$C9:00D8 + n*3  ->  bank:addr ของตาราง pointer ตัวที่ n
ตาราง pointer   ->  pointer 16 บิต ต่อ slot, ชี้ record ในแบงก์เดียวกัน
record          ->  ไบต์ข้อความ จบด้วย $FF (บางที $F7)
```

จำนวน slot ของตารางหนึ่ง ๆ อ่านได้จาก pointer ตัวแรก: pointer แรกคือจุดเริ่มของ pool
ดังนั้น `(pointer แรก − ที่อยู่ตาราง) / 2` คือจำนวน slot โดยไม่ต้องเดา

## เรื่องที่ต้องรู้เกี่ยวกับตารางพวกนี้

**หนึ่งตาราง หลาย descriptor** — entry 9 กับ 10 ไม่ใช่ตารางใหม่ แต่เป็น "หน้าต่าง"
มองตาราง `$CC:7760` ตัวเดียวกันที่ slot 256 และ 512 (entry 5 ก็เป็นหน้าต่างของยูนิต
และ entry 16 เป็นหน้าต่างของ entry 13) **repoint แค่ตัวแรกไม่พอ** รายการอาวุธบนแผนที่
อ่านผ่าน entry 9 ถ้าลืมจะยังเป็นญี่ปุ่นทั้งที่รายงานบอกว่าย้ายแล้ว

**หลาย slot ชี้ record เดียวกัน** — ต้อง repoint ทุก slot ที่ชี้ record นั้น
ไม่ใช่ slot แรกที่เจอ

**ตาราง `$D2` เริ่มที่ที่อยู่คี่** — `$D2:772B`, `$D2:8103` ฯลฯ อย่าปัดให้ตรงคู่

**slot ว่างไม่ใช่พื้นที่ว่าง** — slot ที่ดูเหมือนว่างชี้ไปที่ไบต์ `$FF` โดด ๆ
ถ้าเอา record ไปวางตรงนั้น ช่องที่เคยว่างจะกลายเป็นมีข้อความโผล่มาบนจอ

**`FB aa bb` = แทรก record จาก catalog** — `bb` คือหมายเลข catalog, `aa` คือหมายเลข
record ตัวจัดการฝั่งเมนูอยู่ที่ `$C1:8DBA`/`$C1:8DF3` ส่วนฝั่งฉากต่อสู้มีตัวของตัวเอง
ที่ `$C1:9381` — สองตัวนี้ **ไม่แชร์กัน** operand ช่วง `$8000`–`$81FF` คือชื่อ runtime
(ชื่อผู้เล่น/ชื่อยูนิต) ที่อ่านผ่านตาราง pointer 24 บิตที่ `$C1:8E6E` stride 3

## สคริปต์เนื้อเรื่อง

อยู่คนละระบบกับ catalog: ตารางแม่ 52 ช่อง ช่องละ 3 ไบต์ที่ `$E8:0000`
แบ่งเป็น 47 บล็อก รวม **9,400 ข้อความ** ข้อมูลถอดไว้ครบใน
`data/translations/script.source.json` (ต้นฉบับ) และ `script.th.json` (คำแปล)
