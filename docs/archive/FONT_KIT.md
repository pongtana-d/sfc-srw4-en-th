# ยกฟอนต์ไทยออกไปใช้ที่อื่น

ตัวอักษรไทยในโครงการนี้ถูกวาดและเกลาบนตาราง 8x16 มาตลอด และมันไม่ได้ผูกกับ
SRW4 เลย สิ่งที่ผูกกับเกมคือ *รหัสไบต์*, *pointer table* และ *renderer 65816*
ต่างหาก เมื่อแยกสองอย่างนี้ออกจากกัน รูปตัวอักษรก็ยกไปใช้กับเกมอื่นหรือม็อดอื่นได้

```bash
python3 tools/export_font_kit.py
python3 build/font-kit/shape.py "ฮึดสู้"
```

ผลลัพธ์อยู่ที่ `build/font-kit/` เป็น generated ห้ามแก้ด้วยมือ

## สามชั้นที่ต้องแยกออกจากกัน

| ชั้น | อยู่ที่ไหน | ยกไปใช้ที่อื่นได้ไหม |
| --- | --- | --- |
| รูปตัวอักษร + ระยะ | `font/thai.json` | ได้ทั้งหมด — คือของที่ export ออกไป |
| กฎการวางวรรณยุกต์ | `srw4th/renewal/atlas.py` | ได้ — เขียนเป็นสเปกไว้ใน `SHAPING.md` ของชุด |
| การแพ็กลง ROM | `font/encoding.json`, `renewal-clusters.json`, `srw4th/asm` | ไม่ได้ และไม่ควร — เป็นของ SRW4 เท่านั้น |

## ชุดที่ export ออกมามีสองรูปแบบ

- **atomic** — base กับ mark แยกกันตามที่วาด mark เป็น combining glyph กว้าง 0
  เหมาะกับปลายทางที่จัดวางวรรณยุกต์เองได้ (`srw4-thai-8x16.bdf`)
- **composed** — cluster ละ 1 บิตแมป 1 advance วางเสร็จแล้วตั้งแต่ตอน build
  อยู่ในย่าน PUA ($E000 ขึ้นไป) เหมาะกับปลายทางที่ไม่มี shaper ซึ่งคือเกือบทุก
  game engine และ ROM hack (`clusters.json`, `atlas.png`, `raw/*.bin`)

ชุด composed มี 2,549 cluster = พยัญชนะ x สระบน/ล่าง x วรรณยุกต์/การันต์
ครอบคลุม 563 cluster ที่ ROM ตัวนี้ใช้จริงครบทุกตัว (`tests/test_font_kit.py`
ตรวจข้อนี้ทุกครั้ง)

## ย้ายไปเกม SFC อีกเกม

ของที่ยกไปได้คือ *รูปตัวอักษร* ส่วนที่ต้องทำใหม่ทุกเกมคือ *หน้าฟอนต์กับตารางรหัส*
เพราะแต่ละเกมมี slot ไม่เท่ากันและวางฟอนต์คนละที่ `page.py` ในชุดทำส่วนแรกให้:

```bash
python3 build/font-kit/page.py --first-code 0x80 --slots 96 script.txt
```

มันวัดสคริปต์ที่จะแปลก่อน แล้วแจกรหัสให้ cluster ที่ใช้บ่อยที่สุดจนเต็ม slot
ได้ `page-2bpp.bin` (หรือ `--bpp 4`), `page.tbl`, `page-advance.bin` และ
`page.json` ที่บอกว่า cluster ไหนไม่ได้รหัส — วิธีเดียวกับที่โครงการนี้เลือกว่า
จะใช้ shorthand กับ cluster ไหน

ที่ยังต้องทำเองในเกมใหม่: หาที่อยู่ฟอนต์ใน ROM, ดูว่าฟอนต์เป็น 2bpp/4bpp และสูงกี่
pixel (ชุดนี้เป็น 8x16 = tile บน+ล่าง ถ้าเกมนั้นใช้ 8x8 ต้องวาดใหม่), แล้ววาง
renderer — ถ้าอยากได้ VWF ต้องแพตช์ตัววาดของเกมให้อ่าน `page-advance.bin`

## ทำไมถึงเชื่อได้ว่าตรงกับในเกม

ชุด composed ประกอบด้วย `renewal.atlas.compose_cluster` ตัวเดียวกับที่ build ROM
และเทสต์อ่านบิตแมปกลับออกมาจาก *ไฟล์ที่ export แล้ว* (manifest + `raw/glyphs-1bpp.bin`,
BDF, PNG atlas, 2bpp) เทียบกับ compose_cluster ทีละ cluster ทั้ง 563 ตัว
`proof.txt` ในชุดก็ render ผ่าน `shape.py` ที่แจกไปด้วย ไม่ใช่ผ่าน renderer ของ repo
ถ้า export พัง proof จะพังตาม

## เรื่องสิทธิ์

base ตั้งต้นมาจากการ rasterise ฟอนต์ TTF ที่ระบุใน `font/config.json` แล้วเกลาด้วยมือ
ดังนั้นชุดนี้เป็นงานดัดแปลง ต้องดูเงื่อนไขของฟอนต์ต้นทางก่อนแจกจ่าย รายละเอียดและ
ทางออกถ้าเงื่อนไขไม่เปิด อยู่ใน `PROVENANCE.md` ที่ export ไปพร้อมชุด
ไม่มีพิกเซลใดในชุดนี้มาจาก ROM — ตัวอักษรละติน/ตัวเลขที่ยืมจากฟอนต์เกม (`stock:`)
ถูกกันออกตั้งแต่ต้นทาง เทสต์เฝ้าดูทุกไฟล์ที่ exporter เปิดอ่านเพื่อยืนยันข้อนี้
