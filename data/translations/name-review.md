# รายงานตรวจชื่อ SRW4 ภาษาไทย

> สถานะ: กำลังตรวจใหม่ทั้งหมด — **ยังห้ามถือว่า `reviewed_exact` หรือ
> `reviewed_roman` แปลว่าชื่อถูกยืนยันแล้ว** เพราะค่านี้บอกเพียงวิธีที่เคยใช้สร้าง
> รายการ ไม่ใช่หลักฐานจากเจ้าของผลงาน

## กติกาที่ใช้

1. ถ้ามีชื่อไทยทางการจากเจ้าของสิทธิ์ ให้ใช้ชื่อนั้นก่อน
2. ถ้าไม่มีชื่อไทยทางการ ให้ยึดชื่อโรมันทางการและออกเสียงตามภาษาต้นทาง
   ไม่ถอดย้อนจากคาตากานะ
3. ชื่อญี่ปุ่นแท้ให้ยึดคำอ่านภาษาญี่ปุ่นที่ตรวจสอบได้
4. glossary หลักเก็บชื่อเต็ม ส่วน `rom-glossary.th.json` ใช้ชื่อย่อได้เฉพาะเมื่อ
   วัดแล้วว่าเกินช่องจริงใน ROM
5. ต้องตรวจชื่อเดียวกันใน `glossary.th.json`, `pilots.th.json`,
   `units.th.json`, ป้ายผู้พูดใน `script.th.json` และ glossary ที่ build แล้ว

ลำดับหลักฐาน: ไทยทางการของเจ้าของสิทธิ์ → ชื่อโรมันทางการของเจ้าของผลงาน →
Akurasu/Jiangsheng สำหรับระบุตัวละครใน SRW4 → คาตากานะญี่ปุ่นเมื่อไม่มีข้อมูลอื่น

## ขอบเขตบัญชีที่ต้องตรวจ

- `glossary.th.json` มีคีย์ที่ปล่อยผลจริง 333 คีย์: ตัวละคร 93, ป้ายต่อสู้ 43,
  องค์กร 25, เมคา 54, ชื่อเมคาเต็ม 4, ยาน 10, สถานที่ 33, ศัพท์เฉพาะ 20
  และคำยืม 51
- เมื่อรวมตารางนักบินและยูนิต ระบบ build สร้าง glossary ที่ใช้จริง 1,086 คีย์
  โดยมี 784 คีย์ที่ถูกเรียกจากบทเกม
- ตารางนักบินมี 290 ช่องและตารางยูนิตมี 295 ช่อง รวมช่องชื่อผู้เล่นแบบไดนามิก
  และช่องว่างของเกมเดิมด้วย
- ตารางด้านล่างนับเป็น “ตรวจแล้ว” เฉพาะรายการที่มีหลักฐานกำกับเท่านั้น
  จำนวนแถวไม่เท่ากับจำนวนคีย์ เพราะบางแถวรวมชื่อหลายรูป; จึงยังห้ามสรุปว่าครบ
  จากจำนวนแถวเพียงอย่างเดียว

## ขอบเขตที่ยังเหลือ

- บัญชี build 1,086 คีย์มีสถานะครบแล้ว: คงเดิม 754 และยืนยันว่ามีปัญหา 332;
  คีย์รอยืนยันเหลือศูนย์ ไม่มีคีย์ตกหล่น และไม่มีสถานะชนกัน

- หลังปิดหลักฐานครบและผู้ใช้อนุมัติรายงาน จึงแก้ทุก layer, วัดความกว้าง
  ประกอบ ROM ใหม่ และตรวจข้อความที่ได้จริงจาก ROM อีกครั้ง
