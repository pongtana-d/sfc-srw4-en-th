# คำสั่งตรวจและแก้คำแปลคำอธิบายพลังจิต (spirit descriptions)

เอกสารนี้เป็น**คำสั่งงาน** สำหรับ AI ที่จะมาตรวจและแก้ไฟล์
`translations/spirit-descriptions.th.json` ไม่ใช่รายงานสถานะ
อ่านให้จบก่อนแก้ไฟล์ และห้ามข้ามขั้นตอนตรวจสอบท้ายเอกสาร

ปัญหาที่เป็นต้นเหตุของงานนี้: คำแปลชุดปัจจุบันหลายรายการ**ไม่ได้อิงต้นฉบับ
ญี่ปุ่นที่อยู่ใน ROM** บางรายการเติมข้อมูลจากความรู้ทั่วไปเรื่อง Super Robot
Wars เข้าไปเอง บางรายการตัดคำบอกขอบเขต (ใคร/กี่ตัว/กี่ครั้ง) ทิ้งจนความหมาย
เปลี่ยน งานนี้คือไล่ตรวจทีละรายการเทียบต้นฉบับ แล้วแก้ให้ตรง

## 1. ไฟล์และขอบเขตงาน

| ไฟล์ | บทบาท |
|---|---|
| `translations/spirit-descriptions.th.json` | ไฟล์เดียวที่ได้รับอนุญาตให้แก้ |
| `tools/build_thai_weapons.py` | ตัว build ที่ฝังข้อความลง ROM (`install_map_spirit_messages`) |
| `tools/validate_thai_build.py` | ตัวตรวจ static หลัง build |
| `translations/pilot-status.th.json` | ศัพท์ที่อนุมัติแล้วบนหน้า Pilot Status ใช้เป็นคลังคำอ้างอิง |
| `translations/pilot-status-review.md` | บันทึกการอนุมัติศัพท์ชุดเดิม |

ไฟล์ `spirit-descriptions.th.json` มีข้อมูลสองชั้นที่**กฎไม่เหมือนกัน**

### ชั้น A — `script_messages[]` (ข้อความจริงใน ROM)

29 รายการ เป็นข้อความที่แสดงในหน้าต่างเลือกพลังจิตบนแผนที่ ถูก patch ทับ
ต้นฉบับที่ PC `0x0CAF78..0x0CB2B4` โดยตรง

| ฟิลด์ | แก้ได้ไหม |
|---|---|
| `spirit_id`, `source`, `source_pc`, `source_hex` | **ห้ามแก้เด็ดขาด** — เป็นหลักฐานจาก ROM ตัว build จะเทียบ `source_hex` กับ ROM สะอาดและ error ถ้าไม่ตรง |
| `translation` | แก้ได้ (คือเป้าหมายของงานนี้) |

`source` คือต้นฉบับญี่ปุ่นที่ถอดจาก ROM — **นี่คือแหล่งความจริงเพียงแหล่งเดียว
ของชั้น A**

### ชั้น B — `spirits[]` (เอกสารอ้างอิง 30 รายการ)

ไม่ถูกฝังลง ROM ใช้เป็นเอกสารประกอบทีมแปล

| ฟิลด์ | แก้ได้ไหม |
|---|---|
| `id`, `source`, `sp` | ห้ามแก้ (ชื่อคำสั่งญี่ปุ่นและค่า SP) |
| `translation` | **ห้ามแก้ในงานนี้** — เป็นชื่อพลังจิตที่อนุมัติและ patch ลงหน้า Pilot Status แล้ว (ดู `translations/pilot-status.th.json`) การแก้จะทำให้สองหน้าจอไม่ตรงกันและอาจล้นกรอบ ถ้าเห็นว่าผิดจริงให้**รายงาน ไม่ต้องแก้** |
| `description` | แก้ได้ |

## 2. กฎการแปล (บังคับ)

### G1 — แปลจากต้นฉบับ ห้ามเติมความรู้ภายนอก
แปลเฉพาะสิ่งที่ `script_messages[].source` พูดไว้ ห้ามเติมกลไกที่รู้มาจาก
เกมภาคอื่น เว็บ wiki หรือการทดลองเล่น แม้จะ "ถูกตามระบบเกม" ก็ตาม
ถ้าเห็นว่าต้นฉบับกำกวมหรือไม่ครบ ให้แปลตามต้นฉบับ แล้ว**เขียนข้อสังเกตไว้ใน
รายงาน** ไม่ใช่เติมลงคำแปล

### G2 — ห้ามตัดคำบอกขอบเขต
ต้องรักษาไว้ให้ครบทุกครั้งที่ต้นฉบับมี:

| ญี่ปุ่น | ความหมายที่ห้ามหาย |
|---|---|
| `自分の` | ตัวเอง |
| `指定した ユニット` | ยูนิตที่เลือก (หนึ่งตัว) — **ไม่ใช่ทั้งทีม** |
| `味方全ての` | พันธมิตรทั้งหมด |
| `隣接した` | ที่อยู่ติดกัน |
| `範囲内 / 一定範囲内` | ในระยะที่กำหนด — **ห้ามแปลว่า "ทั้งหมด"** และห้ามระบุตัวเลขช่องเอง |
| `（敵含む） / （味方含む）` | รวมศัตรู / รวมพวกเดียวกัน — เป็นสาระสำคัญ ห้ามตัด |
| `１回だけ` | ครั้งเดียว |
| `１タ－ンの間` | เป็นเวลา 1 เทิร์น |
| `１体` | 1 ยูนิต |
| `選択可能` | เลือกเป้าหมายได้ |
| `防御無視` | เพิกเฉยค่าเกราะ |
| `相手` | เป้าหมาย (ต้นฉบับไม่ได้เจาะจงว่าศัตรู) |

### G3 — ใช้ศัพท์ให้ตรงกับที่อนุมัติไปแล้ว
ยึดตาม `translations/pilot-status.th.json`:

| ญี่ปุ่น | ไทยที่ใช้ |
|---|---|
| 気力 | กำลังใจ |
| 命中(率) | แม่น |
| 回避(率) | หลบ |
| 技量 | ทักษะ |
| レベル | เลเวล |
| 移動力 | เคลื่อนที่ |
| 装甲 | เกราะ |
| ユニット | ยูนิต |
| ＨＰ / ＥＮ / ＳＰ | HP / EN / SP (คงอักษรละติน) |
| ダメ－ジ | ดาเมจ |
| タ－ン | เทิร์น |

ถ้าที่ว่างไม่พอจริงจนต้องย่อ (เช่น `กำลังใจ` → `ใจ`) ให้ย่อได้ แต่ต้องย่อ
**แบบเดียวกันทุกรายการ** และบันทึกคำย่อที่ใช้ไว้ในรายงาน

### G4 — ตัวเลขและเครื่องหมาย
ใช้เลขอารบิกครึ่งความกว้าง (`1` ไม่ใช่ `１`) เพราะหน้านี้ใช้ glyph ไทย/ละติน
ของโปรเจกต์ เศษส่วนเขียน `1/3` เท่าตัวคูณเขียน `x2` ช่วงค่าเขียน `10-1000`
ตามที่ชุดเดิมทำไว้ และคงรูปแบบนี้ให้เหมือนกันทั้ง 29 รายการ

### G5 — ชั้น B ต้องไม่ขัดกับชั้น A
`spirits[].description` เขียนยาวได้ (ไม่มีข้อจำกัดพื้นที่) แต่ต้อง**ตั้งต้น
จากต้นฉบับญี่ปุ่นเดียวกัน** และห้ามระบุตัวเลข/เงื่อนไขที่ต้นฉบับไม่ได้พูด
สำหรับ `id: 30` (奇跡) ไม่มีข้อความคำอธิบายใน ROM ให้เขียน description โดยระบุ
ให้ชัดว่าอ้างจากผลรวมของพลังจิตอื่น และหมายเหตุว่า "ไม่มีต้นฉบับใน ROM"

## 3. ข้อจำกัดทางเทคนิค (ถ้าผิด build จะพัง)

### T1 — งบพื้นที่ต่อข้อความ
ข้อความไทยเข้ารหัสเป็น **1 ไบต์ต่อ 1 cell (8x16 พิกเซล)** บวก 1 ไบต์นำหน้า
สำหรับเข้าโหมด escape page `$FF:C000` ตัว build บังคับว่า

```
จำนวน cell + 2  ≤  จำนวนไบต์ของ source_hex
```

พูดอีกแบบ: `จำนวน cell ≤ (ไบต์ของ source_hex) − 2`
ถ้าเกิน `install_map_spirit_messages()` จะโยน error ทันทีตอน build

**ความกว้างการแสดงผลก็คุมด้วยกฎเดียวกัน** เพราะ 1 ไบต์ของต้นฉบับญี่ปุ่นเท่ากับ
1 cell พอดี (คานะ/สัญลักษณ์ = 1 ไบต์ = 1 cell, คันจิ = 2 ไบต์ = 2 cell)
ดังนั้นถ้าอยู่ในงบไบต์ ก็อยู่ในความกว้างบรรทัดเดิมของญี่ปุ่นแน่นอน

### T2 — วิธีนับ cell (สำคัญมาก อย่านับเป็นตัวอักษร)
1 cell = พยัญชนะ/สระ/ตัวเลข 1 ตัว **บวก**เครื่องหมายกำกับที่ตามมา
(Unicode category `M` — ไม้เอก ไม้โท ไม้ไต่คู้ สระบน สระล่าง การันต์)

- `เต็ม` = `เ` + `ต็` + `ม` = **3 cell**
- `ครั้ง` = `ค` + `รั้` + `ง` = **3 cell**
- `ศัตรู` = `ศั` + `ต` + `รู` = **3 cell**
- สระหน้า (`เ แ โ ใ ไ`) และสระหลัง (`า ะ ำ ๆ`) นับแยกเป็น cell ของตัวเอง
- ช่องว่าง ` ` นับ 1 cell

### T3 — glyph ต้องมีอยู่แล้ว
ทุก cluster ที่ใช้ต้องมี glyph ใน `font/overrides.json`, `font/additions.json`,
`font/menu-special.json` หรือ `font/status-special.json` ถ้าไม่มี build จะ error
`missing map spirit-message glyph` ให้เลี่ยงไปใช้คำที่ใช้ cluster เดิมก่อน
การวาด glyph ใหม่ (ผ่าน `python3 tools/font_glyph_editor.py`) อยู่นอกขอบเขต
งานนี้ ถ้าจำเป็นจริงให้รายงานแทน

### T4 — งบหน้า VWF
หน้า `$FF:C000` รับ cell ที่ไม่ซ้ำกันได้สูงสุด **244 cell** ปัจจุบันใช้ 75 cell
จึงยังเหลือเยอะ แต่ถ้าเพิ่มคำที่ใช้ cluster แปลกใหม่จำนวนมากให้เช็กตัวเลขนี้ด้วย

### T5 — โครงสร้าง JSON
คง key เดิม ลำดับเดิม และจำนวนรายการเดิม (30 spirits / 29 script_messages)
เขียนไฟล์เป็น UTF-8 ไม่ escape ยูนิโค้ด (`ensure_ascii=False`) เยื้อง 1 space
ให้เหมือนไฟล์เดิม เพื่อให้ diff อ่านรู้เรื่อง

## 4. ข้อควรระวังเฉพาะจุด

1. **`ทีม` ไม่เท่ากับ `ที่เลือก`** — id 4 (`味方全て`) กับ id 5 (`指定した
   ユニット`) ตอนนี้แปลเหมือนกันทั้งคู่ ซึ่งผิด
2. **วงเล็บในต้นฉบับคือสาระ ไม่ใช่หมายเหตุ** — `（敵含む）` แปลว่าโดนศัตรูด้วย
   ถ้าเขียนว่า "เพื่อน" อย่างเดียวคือแปลผิด (id 18, 22, 23, 25)
3. **อย่าใส่ตัวเลขที่ต้นฉบับไม่มี** — `範囲内` ไม่ได้บอกว่า 3 ช่อง,
   `手加減` ไม่ได้บอกว่าเหลือ HP 10
4. **ต้นฉบับบางอันไม่ระบุว่า "ศัตรู"** — id 7 เขียนแค่ `全てに`, id 27 เขียน
   `相手` ให้แปลตามที่เขียน
5. **ห้ามยุ่งกับ `<...>` หรือ token พิเศษ** — ข้อความชุดนี้ไม่มี control code
   แต่ถ้าเจอในอนาคตให้คงไว้ทุกตัว
6. **อย่าปรับ `translation` ของ `spirits[]`** ตามข้อ ชั้น B ด้านบน
7. **ห้ามแตะฟิลด์ `source_hex` เพื่อ "ขยายที่ว่าง"** — พื้นที่นี้ตรึงตาม ROM
   ต้นฉบับ ถ้าคำแปลยาวเกินให้ย่อคำ ไม่ใช่ย่อกฎ

## 6. ขั้นตอนทำงาน

1. ดึงตารางเทียบขึ้นมาดูก่อนแก้ (แสดง cell ที่ใช้ / เพดาน):

```bash
python3 - <<'PY'
import json, unicodedata
d = json.load(open("translations/spirit-descriptions.th.json"))
def cells(t):
    return sum(1 for ch in t if not unicodedata.category(ch).startswith("M"))
for m in d["script_messages"]:
    cap = len(bytes.fromhex(m["source_hex"].replace(" ", ""))) - 2
    flag = "OVER" if cells(m["translation"]) > cap else "ok"
    print(f'{m["spirit_id"]:2d} {cells(m["translation"]):2d}/{cap:2d} {flag:4s} {m["source"]} -> {m["translation"]}')
PY
```

2. ไล่แก้ทีละรายการตามกฎข้อ 2 และ 3 โดยดู `source` เป็นหลัก
3. รันคำสั่งข้อ 1 ซ้ำ ต้องไม่มีบรรทัด `OVER`
4. build และ validate ต้องผ่านทั้งคู่:

```bash
python3 tools/build_thai_weapons.py \
  --input "rom/Dai-4-ji Super Robot Taisen (Japan) (Rev 1).sfc" \
  --output "build/SRW4-TH.sfc" \
  --report "build/SRW4-TH.json"
```

```bash
python3 tools/validate_thai_build.py \
  --input "rom/Dai-4-ji Super Robot Taisen (Japan) (Rev 1).sfc" \
  --output "build/SRW4-TH.sfc" \
  --report "build/SRW4-TH.json"
```

## 7. รูปแบบรายงานที่ต้องส่งกลับ

เขียนสรุปเป็นข้อความ (ไม่ต้องสร้างไฟล์ใหม่) ประกอบด้วย

1. ตารางรายการที่แก้: `id | ต้นฉบับ | ของเดิม | ของใหม่ | เหตุผล`
2. รายการที่**ตรวจแล้วไม่แก้** พร้อมเหตุผลสั้น ๆ
3. จุดที่ต้นฉบับกำกวมและการตัดสินใจที่เลือก
4. คำย่อที่ใช้ (ถ้ามี) และเหตุผลด้านพื้นที่
5. ผลรัน build/validate และตัวเลข cell สูงสุดที่ใช้เทียบเพดาน
6. สิ่งที่พบว่าน่าจะผิดแต่**อยู่นอกขอบเขต** (เช่นชื่อพลังจิตใน `spirits[].translation`
   หรือ glyph ที่ยังไม่มี) — รายงานอย่างเดียว ห้ามแก้เอง

> ห้ามรายงานว่า "เสร็จแล้ว" ถ้ายังไม่ได้รัน build และ validate จริง
